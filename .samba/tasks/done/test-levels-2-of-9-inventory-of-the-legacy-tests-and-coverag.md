# Test levels 2 of 9: inventory of the legacy tests and coverage baseline (ADR 0016)

Read CLAUDE.md, docs/spec/architecture.md and ADRs 0011, 0012 and 0016 first (ADR 0016 defines the four test levels: unit, component, integration, end-to-end; integration and e2e stay few; a test goes to the lowest level that can show the behavior). This task is part of a chain that rewrites the test suite from scratch, strangler style: the old tests are moved to tests/legacy/ in task 1 and are NOT edited or deleted until task 8, and new tests are written under tests/unit, tests/component, tests/integration and tests/e2e using the legacy tests as the behavior inventory and the code as the source of truth. The program behavior and src/ do not change (only tests, docs, pyproject for dev dependencies). pyright stays at 0 errors and the whole suite stays green. Plan steps may use only commands in the WORKFLOW.md allow list: git mv and git rm are allowed (git mv needs the target directory to exist: create it by writing a file in it, there is no mkdir), no sed -i, no pipes or redirects, no uv add, uv lock, uv sync or uv run python; uv run pytest with options such as --collect-only, --durations, --cov is fine. If the work is too big for one run at the per-task cost cap, propose chained subtasks in the plan. For tasks that write new tests, the plan must list them as a table (new test | level | behavior | legacy tests it replaces), account for every inventory entry of the area (covered by a new or existing test, or dropped with a stated reason), keep integration and e2e tests to what only that level shows, and say what is covered by existing tests so nothing is duplicated.

Inventory and baseline. (1) Add pytest-cov to the dev dependency group by editing pyproject.toml (do not run uv add; uv run pytest re-locks and syncs itself). (2) Create tests/migration/inventory.json: one entry per test function in tests/legacy (key file::function; parametrized cases are one entry), with: a one-line description of the behavior it checks (read each test, derive it), the level it should live at under ADR 0016 (component, integration, e2e or unit) and why in a few words, status todo, and empty fields for covered_by (list of new or existing test ids file::function) and reason. Group by area so later tasks can find theirs: core rules and run flow, commands, integration contracts per port, end-to-end. Where an existing in-process test already covers the behavior, say so in a note (the later task will confirm). (3) Record the baseline: line and branch coverage of src/samba from running the legacy suite plus the current in-process tests (run it in pieces with --cov-append if one run is too long, using only uv run pytest options), saved as tests/migration/baseline_coverage.json with per-module percentages. (4) Add a temporary check tests/checks/test_migration_inventory.py that fails when a test function in tests/legacy is missing from the inventory or an inventory entry points to a missing legacy test, when a status is not todo, covered or dropped, when a covered entry names no test or a test id that does not exist (found statically with ast), or when a dropped entry has no reason. Update CLAUDE.md and the architecture spec chapter to mention tests/migration as temporary.
