# Test levels 7 of 9: the small end-to-end suite (ADR 0016)

Read CLAUDE.md, docs/spec/architecture.md and ADRs 0011, 0012 and 0016 first (ADR 0016 defines the four test levels: unit, component, integration, end-to-end; integration and e2e stay few; a test goes to the lowest level that can show the behavior). This task is part of a chain that rewrites the test suite from scratch, strangler style: the old tests are moved to tests/legacy/ in task 1 and are NOT edited or deleted until task 8, and new tests are written under tests/unit, tests/component, tests/integration and tests/e2e using the legacy tests as the behavior inventory and the code as the source of truth. The program behavior and src/ do not change (only tests, docs, pyproject for dev dependencies). pyright stays at 0 errors and the whole suite stays green. Plan steps may use only commands in the WORKFLOW.md allow list: git mv and git rm are allowed (git mv needs the target directory to exist: create it by writing a file in it, there is no mkdir), no sed -i, no pipes or redirects, no uv add, uv lock, uv sync or uv run python; uv run pytest with options such as --collect-only, --durations, --cov is fine. If the work is too big for one run at the per-task cost cap, propose chained subtasks in the plan. For tasks that write new tests, the plan must list them as a table (new test | level | behavior | legacy tests it replaces), account for every inventory entry of the area (covered by a new or existing test, or dropped with a stated reason), keep integration and e2e tests to what only that level shows, and say what is covered by existing tests so nothing is duplicated.

Area: end-to-end, the real samba command as a subprocess. Write a fresh, small suite under tests/e2e with its own minimal sandbox helper (a temporary git repository with a WORKFLOW.md and the scripted fake claude from tests/fakes), not the legacy Sandbox. Keep ADR 0009 mechanics: SAMBA_CMD replaces the command under test, tests assert on files, exit codes, stdout and stderr and the calls the fake claude recorded, and never import samba. Cover only what the whole process shows, taking the entries the inventory marks as e2e: the command surface (names, arguments and options, help shape, usage errors exit 2, --repo placement), exit codes and the stdout versus stderr split for a refusal, a missing or broken WORKFLOW.md, a missing claude binary, shell completion driven through the environment (_SAMBA_COMPLETE) including silence with no repo, --show-completion, tty prompts on a pseudo terminal (task discard, task new, work accept), refusal without a tty, signals (stop of a live agent, SIGINT shutdown returns the task), samba run --exit-when-idle, and three or four journeys (for example task new, plan, work, work accept to done; a question round; a retry then give-up). Each test carries a one-line docstring saying what only the e2e level shows. Add a check under tests/checks that the e2e folder holds at most about 45 tests (the budget), and keep the manual drift test (every subcommand mentioned in docs/manual.md) in the e2e folder. Update the inventory entries of this area (covered with ids, or dropped with a reason). Do not edit or delete anything under tests/legacy.
